# Қорғауға дайындық

## Қысқаша таныстыру

«Жобаның мақсаты — қалалық емхана пациенттерінің картотекасын жүргізу. Python негізгі тіл ретінде, SQLite деректерді тұрақты сақтау үшін, ал Streamlit қазақ тіліндегі интерфейс жасау үшін қолданылды. Пациенттер, дәрігерлер, қабылдаулар және медициналық жазбалар төрт өзара байланысты кестеде сақталады. Интерфейстегі әр операция нақты SQL сұранысын орындайды.»

## Көрсету реті

1. `python -m streamlit run app.py` арқылы қосып, localhost:8501 ашыңыз.
2. Әкімшімен кіріп, бастапқы 8/6/12/10 көрсеткішін көрсетіңіз.
3. Пациент қосыңыз. Оның мекенжайын өзгертіңіз. Іздеу арқылы табыңыз.
4. Сол пациентті бос күн/уақытқа дәрігер қабылдауына жазыңыз.
5. Медициналық жазба қосып, пациенттің толық картасын ашыңыз.
6. Дәрігер жүктемесі мен диагноз диаграммасын көрсетіңіз.
7. SQL бөлімінен JOIN, GROUP BY/HAVING және BETWEEN сұраныстарын іске қосыңыз.
8. Қайталанатын телефон немесе бос емес қабылдау уақытын енгізіп, валидацияны көрсетіңіз.
9. Байланысы бар пациентті жоюға болмайтынын түсіндіріңіз. Жоюды көрсету үшін бөлек байланыссыз пациент қолданыңыз.
10. Серверді тоқтатып қайта қосыңыз: жаңа мәліметтер сақталғанын көрсетіңіз.
11. Баптаулардан нақты схеманы, рөлдерді және әрекеттер журналын көрсетіңіз.
12. Терминалда тесттерді және уақытша базадағы `python demo.py` демонстрациясын көрсетіңіз.

## Он сұрақ және жауап

**1. Неге SQLite таңдалды?**

Осы жергілікті оқу жобасына бөлек деректер базасы серверін орнату қажет емес. Барлық кестелер бір файлда сақталады. Python-ның стандартты sqlite3 модулі жеткілікті.

**2. Неге төрт кесте бар?**

Пациент, дәрігер, қабылдау және медициналық жазба — әртүрлі объектілер. Оларды бөлу мәліметтің қайталануын азайтады. Бір пациенттің жеке мәліметі әр қабылдауда қайта жазылмайды.

**3. PRIMARY KEY және FOREIGN KEY айырмашылығы қандай?**

PRIMARY KEY жазбаны бірегей анықтайды. FOREIGN KEY басқа кестедегі сол жазбаға сілтейді. Мысалы, appointments.patient_id patients.id өрісіне сілтейді.

**4. Қандай байланыстар қолданылды?**

Пациенттен қабылдауға, дәрігерден қабылдауға және пациенттен медициналық жазбаға — бірден көпке. Пациенттер мен дәрігерлердің көптен көпке байланысы қабылдаулар арқылы іске асады.

**5. SQL injection қалай шектелген?**

Енгізілген мәндер SQL мәтініне біріктірілмейді. sqlite3 параметрлері арқылы беріледі. Сұрыптау және кесте атаулары пайдаланушы мәтінінен алынбай, бекітілген тізіммен тексеріледі.

**6. Транзакция не үшін қажет?**

Жазбаны өзгерту мен оның аудит жазбасы бір операция ретінде сақталады. Қате болса, екеуі де қайтарылады. Бұл жартылай орындалған өзгерістерді болдырмайды.

**7. JOIN және LEFT JOIN айырмасы қандай?**

JOIN сәйкес жазбалары бар қатарларды біріктіреді. LEFT JOIN сол жақ кестенің барлық қатарын сақтайды. Сондықтан жүктеме есебінде қабылдауы жоқ дәрігер де 0 санымен шығады.

**8. GROUP BY және HAVING не істейді?**

GROUP BY бірдей мәндерді топтайды. HAVING дайын топтың жиынтық нәтижесіне шарт қояды. Мысалы, үш және одан көп медициналық жазбасы бар диагноздарды көрсету.

**9. Бағдарламаны жапқанда деректер неге жоғалмайды?**

Деректер SQLite файлына commit арқылы жазылады. Келесі іске қосу сол файлды ашады. Бастапқы деректер бір рет қана енгізіледі; іске қосу кезінде база жойылмайды.

**10. Streamlit интерфейсі қалай жұмыс істейді және жоба шектеуі қандай?**

Streamlit Python арқылы форма, кесте, навигация және диаграммалар жасайды. Виджет әрекеті скриптті қайта орындайды, ал тұрақты мәлімет SQLite-тан оқылады. Жоба localhost-тағы оқу үлгісіне арналған: файл шифрланбаған, нағыз емханадағы толық құпиялылық, дәрігерге тиесілі жеке қолжетімділік және серверлік көп қолданушылы архитектура енгізілмеген.

## Файлдарды түсіндіру

`app.py` — көрініс пен форма; `services.py` — ереже мен CRUD; `database.py` — схема мен қосылым; `queries.py` — есептер; `validation.py` — енгізуді тексеру; `security.py` — парольді қорғау; `seed.py` — тестілік мәлімет; `models.py` — өріс пен рөл анықтамалары. Толық құрылым README-де берілген.
