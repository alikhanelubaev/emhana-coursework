# SQLite жобасын қорғау

1. Курстықтағы төрт кестені `sql/01_schema.sql` арқылы көрсетіңіз. PK жазбаны анықтайтынын, FK кестелерді байланыстыратынын түсіндіріңіз.
2. `python run.py` іске қосыңыз: база ашылады, бастапқы 8/6/12/10 жазба көрсетіледі.
3. `sql/queries/` ішінен WHERE, BETWEEN, GROUP BY/HAVING және үш кестелік JOIN мысалдарын ашыңыз.
4. `doctor_workload` сұранысындағы LEFT JOIN қабылдауы жоқ дәрігерді де көрсететінін түсіндіріңіз.
5. `sql/patient_card.sql` пациент, қабылдау және медициналық тарихтың байланысын көрсетеді.
6. `sql/examples/crud.sql` арқылы төрт негізгі операцияны көрсетіңіз. Соңындағы ROLLBACK демонстрациялық өзгерістерді қайтарады.
7. `python run.py :memory:` арқылы тесттерді іске қосыңыз. Қате телефон, FK, қосарланған қабылдау, туған күн және жою шектеулерін атап шығыңыз.
8. `data/clinic.db` нақты SQLite файлын және интерфейсі бар `streamlit-app` тармағын көрсетіңіз.

## 10 сұрақ және жауап

**1. Неге SQLite таңдалды?** Бір файлда сақталады, бөлек дерекқор сервері қажет емес, транзакциялар мен реляциялық байланыстарды қолдайды.

**2. Неге GitHub-та SQLite емес, SQL деп жазылады?** SQLite — SQL операторларын орындайтын дерекқор жүйесі. Біздің `.sql` файлдарымыз — сол жүйеге арналған сұраныстар.

**3. Python-ның міндеті қандай?** SQL файлдарын ретімен оқиды, параметрлерді береді және нәтижені көрсетеді. Кестелер мен бизнес ережелері SQL ішінде.

**4. PRIMARY KEY мен FOREIGN KEY айырмасы қандай?** PRIMARY KEY бір кестедегі жолды анықтайды. FOREIGN KEY басқа кестеде шынымен бар жолға сілтейді.

**5. Байланысты пациентті жойса не болады?** `ON DELETE RESTRICT` қабылдау немесе медициналық жазба бар кезде жоюды тоқтатады. Тарих кездейсоқ жоғалмайды.

**6. Бір уақытта екі қабылдауды қалай тоқтаттыңыз?** Дәрігер/күн/уақыт және пациент/күн/уақыт өрістеріне бөлек UNIQUE шектеулер қойылды.

**7. CHECK пен TRIGGER не үшін керек?** CHECK бір жолдың пішімін тексереді. Триггер басқа кестедегі туған күнмен салыстыру сияқты ережелерді INSERT/UPDATE алдында орындайды.

**8. JOIN мен LEFT JOIN айырмасы қандай?** JOIN тек сәйкестігі бар жолдарды береді. LEFT JOIN сол жақтағы барлық дәрігерді сақтап, қабылдауы болмаса жүктемесін нөл деп есептейді.

**9. Деректер қайта ашқанда өшпей ме?** Жоқ, `data/clinic.db` сақталады. `app_meta` бастапқы толтырудың бір рет орындалғанын белгілейді.

**10. Тесттер нені дәлелдейді?** Белгілі бастапқы база үшін 37 нәтиже дұрыс екенін және 25 қате операция қабылданбайтынын тексереді. Бұл барлық ықтимал жағдай тексерілді деген сөз емес; нақты қамтылған шарттар SQL тест файлдарында көрінеді.
